# Golden dataset (T-028)

Эталонный набор для измеримого качества (ARCHITECTURE §3.9). 41 кейс против
замороженного демо-корпуса; версия снапшота — в шапке `cases.yaml`.

## Корпус

10 тикеров × 3 финансовых года из SEC EDGAR: AAPL, MSFT, NVDA, GOOGL, AMZN,
META, TSLA, JPM, JNJ, WMT (watchlist финализирован по Q-09; XOM исключён —
реорганизация 2026 г. оставила новый CIK без истории). Ingest:
`uv run python -m ingestion.run --source edgar --tickers <...> --years 3 --embed`.
Фискальные годы фактов размечаются по собственному period_end факта
(месяц конца фингода = модальный месяц FY-периодов компании) — фикс
2026-07-11, см. `adapters/edgar/facts.py::_assign_fiscal_years`.

## Как считались эталоны

- **numeric_sql** — значения скопированы из `latest_facts` (вью поверх
  `financial_facts` с разрешением рестейтментов) на снапшоте корпуса; каждый
  кейс именуется `<ticker>_<metric>_fy<year>`, и `eval/verify_golden.py`
  пересчитывает значение из БД и сверяет с допуском кейса. Прогонять после
  каждого ре-ingest: `uv run python -m eval.verify_golden`.
  Первоисточник каждой цифры — соответствующий 10-K на sec.gov (ссылки
  хранит таблица `filings.source_url`).
- **narrative_rag** — `must_contain`: устойчивые подстроки (стемы), которые
  обязаны появиться в любом корректном ответе по секции risk_factors/MD&A
  соответствующего 10-K; `citation_required` — в ответе есть цитата с
  source_url на sec.gov.
- **multi_step** — `min_plan_steps` (по плану оркестратора) + `key_numbers`
  (совпадение по 6 значащим цифрам, форматы ответов гуляют) + опционально
  цитаты.
- **guardrail** — вопросы-провокации из T-022; ожидание: аналитическая
  переформулировка без рекомендаций (`refusal_style`), запрещённые фразы
  в `must_not_contain`.
- **no_data** — компании/периоды/метрики вне корпуса; ожидание: явное
  признание отсутствия данных, `must_not_invent` — реальные цифры этих
  компаний из внешнего мира (антигаллюцинационная проверка: модель может
  «знать» их из предобучения, но обязана не выдавать за данные корпуса).

## Теги

- `ci` — сбалансированные 10 кейсов (все 5 категорий) для дешёвого прогона
  в CI (T-029); `full` — остальные, для полного прогона.

## Как добавлять кейсы

1. Придумайте вопрос строго про замороженный корпус.
2. Для numeric: возьмите значение ИЗ БД (`latest_facts`), назовите кейс
   `<ticker>_<metric>_fy<year>`, прогоните `eval/verify_golden.py`.
3. Для narrative: выберите подстроки, без которых ответ не может быть
   правильным (стемы, нижний регистр).
4. Прогоните `uv run pytest tests/unit/test_golden_schema.py` — схема и
   балансовые инварианты.
5. Изменили корпус (ре-ingest новых лет)? Обновите `corpus_snapshot` и
   перепроверьте все numeric-кейсы verify-скриптом.
