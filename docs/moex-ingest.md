# Runbook: RU-ingest (MOEX ISS)

T-032. Как наполнить БД рыночными данными MOEX и что такое INGEST_NODE-режим.

## Где запускать: нода с чистым RU-доступом

Доступ к `iss.moex.com` с зарубежных IP бывает нестабилен/блокируется
(ARCHITECTURE.md §5.6), поэтому RU-ingest запускается **только на ноде с
чистым доступом к RU-ресурсам**. По решению владельца (Q-06) это сама
домашняя нода (РФ): выделенный удалённый INGEST_NODE не требуется, но
паттерн остаётся поддержанным — ingestion не привязан к остальному стеку.

INGEST_NODE-режим (общий случай): любая машина, у которой есть
(1) чистый доступ к источнику и (2) сетевой доступ к общей Postgres,
запускает только `ingestion.run` и пишет в общую БД. Оркестратор, воркеры и
UI при этом могут жить на других нодах — им нужна только БД. Отдельного
флага не существует: «режим» — это просто запуск ingest-команды на нужной
ноде с теми же `POSTGRES_*`-переменными в `.env`.

## Команды

```bash
# полный RU-ingest демо-watchlist (SBER, GAZP, LKOH) за 3 года
APP_MODE=ru uv run python -m ingestion.run --source moex \
    --tickers SBER,GAZP,LKOH --years 3
```

`--source moex` можно опустить, если `APP_MODE=ru` — реестр адаптеров сам
резолвит режим в MOEX (config/app.yaml, `adapters.ru: moex`).

Что попадает в БД: компании (доска TQBR), синтетические «филинги»
`MOEX-EOD-<SECID>-<год>` (по одному на календарный год) и факты
`close_price` (за каждый торговый день, `standard='MOEX'`) +
снапшот `market_cap`. Нарратива у MOEX нет: `--embed` не даст чанков,
секции появятся с адаптером e-disclosure (§5.5).

## Особенности

- **Кэш**: `data/cache/moex`; история закрытых торговых дней неизменна и
  кэшируется навсегда, снапшот доски — 1 час. Повторный ingest почти не
  ходит в сеть и идемпотентен (ON CONFLICT по натуральным ключам).
- **Недоступность ISS**: ретраи с backoff внутри клиента; после исчерпания —
  `SourceUnavailableError`, тикер помечается ошибкой, остальные источники и
  тикеры не страдают (изоляция per-ticker в `ingestion.run`).
- **Ключи не нужны**: задержанные данные бесплатны. Лицензия — только
  ознакомительное использование (раздел «Источники данных и лицензии» в
  README).
- **Фикстуры для тестов** пишутся тем же способом и с той же ноды:
  `uv run python scripts/record_moex_fixtures.py`.
